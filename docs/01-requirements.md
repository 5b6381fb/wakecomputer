# WakeComputer 需求文档（最终版 v1.0）

> 安卓多主机远程开关机 App · 基于 OpenWrt Docker 后端 + 标准 Wake-on-LAN
> 文档状态：待评审 · 最后更新：2026-10-17
> 配套文档：[技术方案](02-technical-design.md) · [开发任务清单](03-task-plan.md)

## 1. 背景与目标

### 1.1 背景

家庭/小型办公网络中通常有多台 Windows / Linux 主机，长期处于关机或休眠状态以省电。需要在这些主机未开机时远程唤醒，在运行中远程安全关机/重启，并能在手机上集中查看所有主机的在线状态。

现有 OpenWrt 路由器上已运行 `sub2api`、`PostgreSQL`、`Redis` 等容器，本次新增能力**必须与现有容器和数据完全隔离**，不引入第二个数据库服务，不占用现有端口与数据卷。

### 1.2 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 手机一键唤醒任意 Windows/Linux 主机 | 局域网内唤醒成功率 ≥ 95%（BIOS/NIC 配置正确前提下） |
| G2 | 手机远程关机/重启/取消关机 | 指令下发成功率 ≥ 98%（主机在线且 Agent 正常） |
| G3 | 批量操作 | 支持一次对 2~50 台主机执行唤醒/关机/重启，并给出逐台结果 |
| G4 | 外网安全访问 | 仅通过既有 HTTPS 反向代理暴露，不新增公网端口 |
| G5 | 极致轻量 | 服务端镜像 ≤ 40 MB、常驻内存 ≤ 80 MB、可跑在 256 MB 空闲内存的路由器上 |
| G6 | 零影响 | 现有 sub2api / PostgreSQL / Redis 容器与数据卷零改动、零中断 |

### 1.3 非目标（本期不做）

- 不做屏幕远控、远程桌面、文件传输。
- 不做硬件级带外管理（IPMI / iDRAC / vPro）。
- 不做公网 WoL 中继（后端始终部署在主机所在局域网内）。
- 不提供 Web 管理后台（Android App 为唯一客户端，仅保留初始化 CLI）。
- 不做多租户、多组织、RBAC（本期单管理员）。

## 2. 术语

| 术语 | 说明 |
|---|---|
| WoL | Wake-on-LAN，通过 UDP 魔术包唤醒网卡 |
| 魔术包 | 6 字节 `FF` + 目标 MAC 重复 16 次，共 102 字节 |
| Agent | 安装在被控主机上的轻量守护进程，负责关机/重启/心跳 |
| 广播地址 | 如 `192.168.1.255`，魔术包发往该地址由交换机泛洪到本网段 |
| SSE | Server-Sent Events，服务端单向推送，用于状态实时更新 |
| 反向代理 | 既有 Lucky（gdy666/lucky），负责 TLS 终止与域名路由 |

## 5. 功能需求

### 5.1 账号与安全（FR-AUTH）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-AUTH-01 | 用户名 + 密码登录（Argon2id 校验） | P0 | 正确凭据登录成功；错误凭据返回统一错误且不泄露账号是否存在 |

| FR-AUTH-01b | 网络不通时保持登录态 | P0 | 超时、DNS 失败、5xx 不跳登录页；仅服务端返回 401/403 才要求重新登录 |

| FR-AUTH-04 | 登录失败限流与锁定 | P0 | 单 IP 5 次/分钟；连续 5 次失败锁定 15 分钟并记录审计 |

## 7. 部署约束（硬性）

1. **完全隔离**：独立 compose 项目 `wakecomputer`、独立目录 `/opt/wakecomputer`、独立数据目录，不复用任何现有 network / volume / 容器。
2. **不新增公网端口**：复用 Lucky 既有 443，仅在现有 Web 服务规则下新增 `wake.example.com` 子规则（不新建同端口监听、不改 sub2api 子规则）。
3. **不引入数据库服务**：使用嵌入式 SQLite，避免占用 PostgreSQL 容器与资源。
4. **不触碰现有数据**：禁止执行 `docker system prune`、`docker volume prune`、全局 `docker compose down`。
5. **资源上限**：容器 `mem_limit=128m`、`cpus=0.5`，日志轮转 5 MB × 3。
6. **存储安全**：数据目录必须位于 ext4 的 USB/SSD 挂载点，禁止写在 overlay（闪存磨损）。
7. **回滚能力**：镜像按版本 tag 固定，升级失败可一条命令回退上一版本。
8. **网络模式**：使用 `network_mode: host` 以保证 WoL 广播能到达 LAN（理由见技术方案 §4.3）。
